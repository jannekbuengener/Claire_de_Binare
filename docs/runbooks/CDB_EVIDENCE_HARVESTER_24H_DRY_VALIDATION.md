# CDB Evidence Harvester — 24h Dry Validation Runbook

## Purpose

Prove 24h dry collection of evidence harvester artifacts **without trading side effects**.

This runbook defines how to validate that the always-on evidence daemon (Issues
[#3345](https://github.com/jannekbuengener/Claire_de_Binare/issues/3345),
[#3346](https://github.com/jannekbuengener/Claire_de_Binare/issues/3346),
[#3347](https://github.com/jannekbuengener/Claire_de_Binare/issues/3347),
[#3348](https://github.com/jannekbuengener/Claire_de_Binare/issues/3348),
[#3349](https://github.com/jannekbuengener/Claire_de_Binare/issues/3349),
[#3350](https://github.com/jannekbuengener/Claire_de_Binare/issues/3350),
[#3351](https://github.com/jannekbuengener/Claire_de_Binare/issues/3351))
collects, snapshots, and alerts without placing orders, starting runtime,
mutating databases, or writing to GitHub.

---

## Preconditions

- All Harvester child slices #3346–#3350 are **merged**.
- Validation checker `tools/evidence_harvester/validation.py` exists on `main`.
- Python 3.12+ is available with dependencies from `requirements.txt` /
  `requirements-dev.txt`.
- The local working tree is on `main` (or a branch derived from `origin/main`)
  with a clean worktree.
- **LR remains NO-GO.** Paper/research scope only.

---

## Required Safety State

| Check | Expected |
|---|---|
| LR status | `NO-GO` |
| Live status | `NO-GO` |
| Echtgeld status | `NO-GO` |
| Runtime actions | `not_allowed` |
| DB execution | `not_allowed` |
| Source mode | `fixture` or `future_readonly` |

All snapshot `safety` fields and `metadata.source_mode` must match these
expectations. The validation module enforces this fail-closed.

## Allowed Run Modes

### 1. Fixture Validation Now (this PR, #3351)

Run the validation checker against a local directory of fixture artifacts to
prove the checker itself works:

```powershell
python -m tools.evidence_harvester.validation validate-dir `
    --artifact-dir "artifacts\evidence_harvester\fixture_validation" `
    --window-start-utc "2026-06-18T16:00:00Z" `
    --window-end-utc "2026-06-19T16:00:00Z" `
    --pretty
```

### 2. Real Local 24h Dry Run (separate Jannek Runtime-GO required)

A real 24h background run is **NOT** authorized by this PR. It requires a
**separate explicit Runtime-GO** from Jannek. When authorized:

1. Install the scheduler task (requires `--explicit`):
   ```powershell
   python -m tools.evidence_harvester.scheduler install --explicit --fixture path\to\input.json
   ```
2. Let the scheduler run for 24 hours.
3. After 24h, validate the collected artifacts:
   ```powershell
   python -m tools.evidence_harvester.validation validate-dir `
       --artifact-dir "artifacts\evidence_harvester\scheduled" `
       --window-start-utc "2026-06-18T16:00:00Z" `
       --window-end-utc "2026-06-19T16:00:00Z" `
       --expected-snapshot-count 1 `
       --json-output "artifacts\evidence_harvester\validation_report.json" `
       --pretty
   ```

> **Guardrail:** No Docker start, no DB mutation, no Redis write, no paper
> runner start, no order/risk/execution action. The scheduler runs the
> fixture-backed snapshot path only.

## Expected Artifacts

After a 24h dry run, the artifact directory should contain:

| Artifact | Pattern | Required |
|---|---|---|
| Collector report | `collector_report_<stamp>.json` | At least 1 |
| Snapshot JSON | `snapshot_<stamp>.json` | At least 1 |
| Snapshot Markdown | `snapshot_<stamp>.md` | At least 1 |
| Alert report | `alert_<stamp>.json` or `alerts_<stamp>.json` | At least 1 (or explicit no-alert evidence) |
| Validation report | `validation_report.json` (optional, generated by the validation CLI) | Recommended |

For the initial fixture validation (this PR), unit test fixtures serve as the
artifact source.

---

## Validation Checks

### Artifact Integrity

- **JSON parse:** Each file must be valid JSON.
- **Schema version:** Snapshot must use `cdb.evidence_harvester.snapshot.v1`;
  alert report must use `cdb.evidence_harvester.alert_report.v1`.
- **Source mode:** Must be `fixture` or `future_readonly`.
- **Timestamps:** `generated_at_utc` (snapshot) and `evaluated_at_utc` /
  `snapshot_generated_at_utc` (alert) must be valid ISO-8601 UTC.

### Safety Flags

- `lr_status` must be `NO-GO`
- `live_status` must be `NO-GO`
- `echtgeld_status` must be `NO-GO`
- `runtime_actions` must be `not_allowed`
- `db_execution` must be `not_allowed`
- Safety banner must match the expected text.

### No-Trading-Side-Effects Check

The artifact JSON is scanned for these forbidden patterns:

- `LR-Go`, `Live-Go`, `Echtgeld-Go`
- `trade_executed`, `order_submitted`, `position_opened`

Any match is a **FAIL**.

### Alert Report

- Must exist OR explicit no-alert evidence must be provided.
- Schema version must match.
- `manual_escalation_only` must be `true`.

### Snapshot Cadence (multi-snapshot windows only)

If multiple snapshots are present, the gap between consecutive snapshots must
not exceed the cadence tolerance (default: 60 minutes).

---

## Pass / Warn / Fail Criteria

| Outcome | Condition |
|---|---|
| **PASS** | All checks pass. No fail or warn findings. |
| **WARN** | At least one warning, but no failures. Examples: missing alert report, timestamps outside window, cadence gap. |
| **FAIL** | At least one failure. Examples: invalid JSON, wrong schema version, safety flag violation, forbidden content, missing snapshots. |

A FAIL verdict means the 24h dry collection is **not proven**. The operator
must investigate the fail-closed reasons reported in the findings.

---

## Side-Effect Checklist

Before and after any run, verify:

- [ ] No Docker container started by the harvester
- [ ] No DB mutation performed
- [ ] No Redis write performed
- [ ] No paper runner started
- [ ] No order placed (paper or live)
- [ ] No risk/execution action triggered
- [ ] No automatic GitHub issue/comment created
- [ ] No LR-Go / Live-Go / Echtgeld-Go implied
- [ ] Artifacts are local JSON/Markdown only
- [ ] Scheduler requires `--explicit` for install

---

## Operator Handoff for Real 24h Dry Run

When Jannek issues the separate Runtime-GO for the real 24h dry run:

1. Confirm scheduler installation with `--explicit`.
2. Verify the scheduler is running (`python -m tools.evidence_harvester.scheduler status`).
3. After 24h, collect artifacts.
4. Run validation:
   ```powershell
   python -m tools.evidence_harvester.validation validate-dir --artifact-dir artifacts\evidence_harvester\scheduled --pretty
   ```
5. Report PASS/WARN/FAIL in the corresponding GitHub issue.
6. If FAIL, investigate findings before re-running.
